# Agent Atelier visual specification

Brand mark: use the original ImageGen pixel-art A/atelier logo in `public/assets/logo.png` for the sidebar and loading screen, and its matching `app/favicon.ico` for browser tabs. Forest green, ivory, and an amber window connect the mark to the office palette. Generation prompt and asset sizes: `logo.md`.

Reference: `concept.png` (1536 × 1024). Thai UI, light ivory application background, white navigation and inspector, forest-green primary action, charcoal content, restrained gray borders. Body and controls use a Thai-capable system sans-serif, 14px controls, 16px reading text, 30px main title, 20px section titles. Spacing uses 4/8/12/16/24/32px; 8px radii and thin borders.

Desktop composition: 200px left rail, fluid main area, 310px selected-member inspector. The primary focal point is a warm wood pixel office. The sidebar holds the project selector and compact Codex status; each page has a compact title and contextual actions. Task creation belongs on the task page. A task board follows the office scene, switching to fewer columns in a narrower panel and stacking on mobile. On smaller screens navigation becomes a collapsible horizontal rail and the inspector stacks after the scene. All interactive labels, status, forms and nameplates are HTML; the office scene is Phaser.

Primary labels: ออฟฟิศของคุณ; ทีม AI ของคุณ พร้อมทำงานไปด้วยกัน; สร้างงาน; พื้นที่ทำงาน; จัดห้อง; เพิ่มสมาชิก; งานในทีม; รอเริ่ม; กำลังทำ; เสร็จแล้ว; ข้อมูลสมาชิก; ตั้งค่าสมาชิก; Model; งานปัจจุบัน; ข้อความถึง; ส่งข้อความ; กิจกรรมล่าสุด. Navigation: ออฟฟิศ, งาน, ทีมแชต, ตารางงาน, ความทรงจำ, การอนุมัติ, โปรเจกต์, เชื่อมต่อ. Icons: Lucide outline, 20px, 1.8px stroke.

Intentional functional extensions: connection/retry status and stop-team action; error/interrupted task state; dedicated pages for agent settings, task creation and details, schedules, projects and approval questions; dialogs for memory and approval review. These reuse the same controls, spacing, palette and typography. Room furniture and characters are separate generated assets so users can rearrange furniture and change avatars. The room is not a flattened screenshot. Character walk routes, progress markers and meeting positions are derived from real runtime state. Reduced-motion preference disables animation.

Avatar editor: member forms offer ตัวละครเดิม / สร้างตัวละคร with pressed button states and paired face/full-body previews. Existing members keep their original sprites until explicitly changed and saved. The local composer uses fixed 32×32 pixel layers scaled to 96×96 without smoothing: one body/outfit, four hair styles (short, bob, long, curly), six skin tones, hair/shirt colors, and optional glasses. Skin swatches have Thai accessible names and a selection border; all controls support keyboard input. Randomize changes only draft appearance, and leaving the form with unsaved changes asks for confirmation. Portraits and office sprites share the renderer and appearance identity. No avatar image uploads, remote generation, standalone avatar image exports, or additional animation states in this version. Avatar settings are included in office backups.

Office backups: สำรองข้อมูล is an additional navigation item using the existing panel and button styles. Export office downloads JSON; a labeled native file input opens an import preview Dialog with counts, missing project paths, and explicit replacement confirmation. Busy controls disable repeat submission, errors use alerts, and progress/results use a live status region. Long paths wrap on mobile. Restored offices show the existing paused-team banner; schedules and Google access require manual review and enabling.

Conversation and planning: reuse the existing chat, task board and task detail page. Draft tasks are shown in the first board column (แผนและคิวงาน) with รอยืนยันแผน. The shared PlanReview displays goal, steps, deliverable, owner, kind, optional assignment list/dependencies, and schedule recurrence. Adjusting text disables confirmation until the revised version is prepared; pending and error states remain visible. Primary action is ยืนยันและเริ่มงาน, or ยืนยันแผนและเปิดตาราง for schedules. Keep controls in HTML and allow long plans to scroll on mobile. The team-room composer names the selected Boss; agent settings offer a single Boss checkbox that replaces the previous selection. The shared Select binds followup messages to an explicit task. Approved assignment batches show รอผลทีม while child work is pending.

Team chat fits the viewport with an independently scrolling message history and a visible composer. The member inspector starts closed; it shares the desktop layout when opened and overlays the chat on narrower screens. Task selection and image attachment sit together above the message field. Opening a conversation and sending a message move to the latest message; incoming messages preserve a reader's position away from the bottom and offer a button to return.

Workflow review: reuse the chat and task detail surfaces with a Thai stage list, criteria, version history, image previews and evidence. Design approval, final acceptance, per-repository merge and closure are separate controls. In Task Detail, the task conversation holds revision feedback, results, evidence and versioned files. The team chat keeps its existing workflow controls. Keep errors visible with role=alert and progress in a status region. Pending design reviews belong in the รอตรวจรับ board column; accepted code remains ตรวจรับแล้ว รอ merge until all repos are merged and the user closes the task. Repository paths and branch names wrap on mobile. Historical files use their explicit delivery revision.

Workflow templates: accepted main tasks offer a reusable template form with empty description and criteria fields. Project-scoped templates are selected and managed in task creation; the new prompt opens an editable draft with member selection and current repositories. Keep the existing confirmation and approval gates visible.

Theme: the sidebar provides system, light and dark choices stored per browser. Dark mode uses dark green-gray surfaces with the existing green accents; the pixel office retains its original colors.

Form layout: dialogs support at most three editable fields, counting repeatable fields and the maximum visible in any state. Longer forms use a dedicated page with Back navigation and a warning before discarding edits. On desktop, member, task, project, and schedule forms group related fields into columns with more room for the main content; they stack in the same input order on smaller screens. Dedicated pages are capped at 1440px.

Task acceptance: new standalone and aggregate results appear in the รอตรวจรับ board column under รอคุณตรวจรับ. The task conversation contains the deliverable and the page provides the explicit acceptance button. Accepted code stays active until all repository merges and explicit closure.
